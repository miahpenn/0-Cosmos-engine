**Status: research-only transcription and bounded preflight; not scientific admission.**

This folder preserves a runnable Python transcription of the corrected GEAR-10 `darksector.py` REV2 listing from the Library PDF named below, together with a small validation harness and its machine-readable result. It is intentionally a separate REV2 artifact; it does not overwrite or relabel the earlier pre-drag-correction GEAR-10 code.

## Reproduce this bounded preflight

Python 3 with NumPy and SciPy are required. The observed environment was Python `3.13.5`, NumPy `2.3.5`, and SciPy `1.17.0`.

From this directory:

```bash
python -m py_compile darksector_REV2.py validate_darksector_REV2.py
python validate_darksector_REV2.py
sha256sum -c SHA256SUMS.txt
python -m pytest -q ../../../tests/test_gear10_rev2_drag_sign_regression.py
```

The extended harness writes `validation_results_r6_sign_discriminator_2026-10-16.json`; it leaves the committed `validation_results_2026-10-16.json` baseline snapshot unchanged. The dedicated `GEAR-10 REV2 rung-6 reproducibility` workflow pins NumPy/SciPy, runs the matrix and regression, and uploads the new machine-readable report. Its R6 integral samples `n = 5000, 20000, 80000` points for `k = 1`, `beta = -0.2`, `lambda = 1`, `D = 0`, `V0 = 2.07`, `a_i = 1e-4`, and `a_f = 1`. It compares the integrated identity

`d/dtau (a*m*theta_dm) = a*m*(k^2*Phi - beta*k^2*delta_phi)`, with `m = exp(-beta*phi)`.

## R6 matrix, negative control, and normalization provenance

The extended harness reproduces the four general-form cases (k, beta) = (1, 0), (1, -0.20), (100, -0.04), and (1000, -0.20) at n = 5000, 20000, and 80000. Each row records the signed balance sides, absolute gap, max-side-normalized residual, sum-of-sides-normalized residual, and descriptive observed refinement order for both conventions.

A test-only in-memory fault injection reverses only the + beta * phi_prime * theta_dm term in the Euler RHS. It reruns selected nonzero-coupling cases against the same integrated R6 identity and records corrected and fault-injected results side by side. The source file itself is never modified by this control. The regression requires the corrected residual to refine while the flipped-sign residual remains large and approximately plateaus.

**Historical normalization mismatch:** the archived R6 table values appear to match abs(lhs-rhs)/(abs(lhs)+abs(rhs)) more closely, whereas the accompanying text describes normalization by max(abs(lhs), abs(rhs)). Since the raw original pre-correction script/result provenance is not fully recovered, this archive reports both denominators and preserves the historical discrepancy instead of silently changing the old table or asserting which convention generated it.

## Explicitly not established

- This is not a reproduction of the complete six-rung validation ladder.
- It does not independently reproduce rung 2 against CAMB. The original GEAR-10 report marked the perturbation CAMB comparison unpaid; that provenance issue is tracked separately on GitHub Issue #5.
- The extended harness covers the four general-form R6 cases documented above, but it does not reproduce R1–R5, the rung-3 growth scan, or the GEAR-12 growth-index experiment. It therefore does not complete the full six-rung validation ladder.
- It does not settle the literature/version/Fourier-convention question about the fifth-force sign. Keep the archive's sign argument separate from an independently sourced derivation.
- It does not validate `beta = -0.04`, which the GEAR-10 note itself marked as lacking a derivation.
- It does not establish production readiness, a bounce/cycle, or scientific admission.

The archived R&D acceptance gate remains: preserve the historical/pre-correction source independently if its exact bytes can be recovered; assemble complete rung-specific harnesses/results against pinned versions; record Python/NumPy/SciPy/CAMB versions where used; and have an independent reviewer reproduce each claimed check. Do not silently reconstruct unavailable files as if they were historical originals.
